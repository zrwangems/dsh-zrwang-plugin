02

勾选一个技能，之后发生什么

从点击到模型看见，中间只有一次落盘和一次重算。侧栏不缓存结论，每次都以后端算出的状态为准。

1
侧栏发出变更
单个技能走 POST /selection，目录批量走 POST /children，整组重置走 POST /reset；请求带 sessionId、cwd 和变更项。
client/tree.mjs
2
接口校验并定位上下文
只接受 catalog 里存在的技能名；解析项目根和 DSH 工作区，激活当前工作区的模式，必要时先为它建一个可编辑模式。
host/routes.mjs
3
写勾选与模式
更新 selection.json；被改动技能所在目录的显式门禁被清掉，回到“按勾选推导”；当前模式的完整选择与门禁写回 presets.json。
state/selection.json
state/presets.json
4
写会话快照
把本次生效的选择与门禁写进当前对话的 session-selection.json，其他对话的快照不动。
host/session-selection.mjs
5
让技能列表失效
invalidateSkillProvider() 通知 DSH：下一次取技能时重新计算，不用重启。
host/skill-provider.mjs
6
提供方重算候选
按 list({ cwd }) 读取目录、勾选、门禁、模式和本会话快照，得到目标技能集合，再为每个技能生成带 SKILL.md 路径的候选。
host/skill-provider.mjs
7
对话拿到新技能表
只有这些候选会出现在当前对话的技能列表里；取消勾选后，下一次列表刷新就不再提供，模型也不会再看到。
agent 技能表

门禁怎么参与

  • 工程 / 科研 / 办公三个一级目录同时是注入总闸，默认关闭。
  • 勾叶子技能不会自动开总闸；一级目录的「全选」会同时打开本组门禁，点一次就能真正开始注入。
  • 子目录的「全选 / 全关」只作用于直接下一层，不递归下钻；搜索过滤时只处理当前可见的节点。
  • 目录复选框按“子树里有没有勾选技能”自下而上推导：空子树未勾选并置灰。

模式怎么参与

  • 模式是「项目 + DSH 工作区」的一组选择模板，存在 presets.json。
  • 「默认」模式只读；在它上面改任何一项，都会落到当前工作区的自动模式，同工作区的对话共享。
  • 自动模式重命名后升级为项目级模式，同项目所有工作区可见；也可以右键基于某个模式新建。
  • 套用模式只改当前对话的选择基线，不会反向覆盖别的对话已经保存的快照。

MathWorks 组件

随工程技能组自动开关：工程组门禁打开、并且确有工程技能注入时，注册 matlab-mcp。工程组关掉即注销。只在 Windows 上可用。

  • 命令：插件包里的 matlab-mcp-server-windows-x64.exe
  • 参数：--matlab-session-mode=existing、Simulink 工具扩展文件
  • 工具：5 个 MATLAB + 9 个 Simulink，共 14 个
  • 前置：MATLAB R2023a+，并在 MATLAB 里执行过 satk_initialize

Windows MCP 组件

手动勾选后注册 windows-mcp，提供桌面截图、快照、点击和窗口操作。取消即注销。

  • 命令：系统 PATH 里的 windows-mcp，参数 serve
  • 插件不自带运行时，需要自行安装（例如 uv tool install windows-mcp）
  • 前置：Windows 桌面会话；其他平台显示不可用

会话隔离

host · mcpManager 两个服务器都在宿主启动，连接参数固定
matlab-mcp · 14windows-mcp
对话 A · 只开 MathWorks 工具表里只有 MATLAB / Simulink 工具
mcp__matlab-mcp__*mcp__windows-mcp__*
对话 B · 只开 Windows MCP 工具表里只有桌面工具
mcp__matlab-mcp__*mcp__windows-mcp__*
怎么算 deny 每次会话选择或工具表变化，插件读取本会话快照，算出本会话没启用的服务器前缀，把这些 mcp__* 工具交给 ctx.tools.restrict。
两层生效 restrict 负责让工具从工具列表、提示词上下文和执行里一起消失；tools/pre-execute 再按同一份选择校验一次，防止工具表正在重连时漏网。
状态展示 组件行显示「启动中 / 已启动（N 个工具）/ 重连中（第 N 次，X 秒后重试）/ 连接失败，X 秒后自动恢复」，并提供「重启」。

断线之后

稳定性分两层，都是 DSH 官方机制。第一层在 mcp-client 内部重连，第二层是插件订阅状态事件后的实例重建。

会拉起多个角色的命令（评审团、流水线、并行改写等）在执行前自动打开 DSH 的「智能体团队协作」，并带上用户已授权的说明；只有无法改动该开关时（例如在子会话里）才提示手动开启。

写作用域护栏 把上游的 PreToolUse hook 搬到 DSH 的 tools/pre-execute

  • 只约束 Bucket A 单阶段角色，并且只在这个角色作为独立子代理运行时生效；主会话、inline 角色和 B/C/D 角色不受这条硬护栏限制。
  • 写入工具（write、edit、apply_patch、str_replace_editor）只能落在清单的 allowed_write_globs 里，通常是自己的 phaseN_*/**。
  • bash、pwsh、terminal_send 一律拒绝。命令串无法可靠区分读写，全拒绝是唯一不会 fail-open 的做法。
  • 逃出会话工作目录的路径拒绝；多文件补丁逐个检查，任一越界整单拒绝；缺文件路径的写入也拒绝，不静默放行。
  • 角色从子代理第一条任务 prompt 识别：优先 ARS-ROLE: <角色名>，其次 frontmatter 的 name:，最后是角色声明。识别不到就只按正文规则执行。
  • 插件自己的护栏文件（阶段清单、guard 脚本、host 里的判定模块）任何 ARS 子代理都不能改。

密钥为什么不进环境变量原名

DSH 的 shell 会清掉名字里带 KEY / TOKEN / SECRET / PASSWORD 的普通环境变量，所以插件注入的是 *_CRED 结尾的变量。

host/pysite/sitecustomize.py 在 Python 启动时把它们映射回上游脚本认识的标准名字。YAML、日志和侧栏都不会出现明文。

Python 与命令转发

插件不自带 Python，也不安装依赖。用户在设置里选本机已有的解释器，插件把静态的 host/shim/python 目录挂到 PATH 前面，python / python3 转给所选解释器。

host/shim/bash 里的 bash / sh 转给 Git Bash 或系统 bash。缺依赖只列出，不自动安装；没有可用解释器时不挂目录，技能会提示未选择。

专利数据目录是必填项。留空时不会创建 patent/，9 个专利技能全部停用；填了之后，Obsidian 库是该路径下的 vault/，索引与模型在 patent-map/，审查答复在 oa/，产物在 outputs/。

每一项是谁写的

  • 插件本体：安装时由 DSH 包管理装进 profile 的 node_modules，包含 host、client、lib、329 个技能、ARS、MathWorks 运行时、目录树和文档。
  • package.json：多一条插件依赖，dsh.profile.bundles 多一条本插件，启动时装配它的补丁层。
  • cordis.patch.yml：本插件条目的 config，设置页保存的非密钥项都在这里。
  • .credentials.yaml：只保存填过的密钥引用，一个密钥一个 ref，YAML 与日志里没有明文。
  • state/：选择、门禁、模式、会话快照、界面状态、Python 候选缓存、ARS 依赖检查、事件日志。插件升级不会删。
  • patent/：只有设置页填了专利数据目录才会使用；不填时连目录都不创建。
  • pnpm 产物：pnpm-lock.yaml 和 .pnpm 是 DSH 包管理的副产物，不是插件写的。

不会再出现的东西

  • 项目目录里的 .agents/skills 与目录联接
  • 插件自己的 settings.json 或配置目录
  • 旧的 $DSH_HOME/zrwang-plugin-config/
  • 插件包内的 cache/；旧版本的会一次性迁到 storages 后删除
  • YAML、日志、侧栏里的明文密钥

卸载时

dsh plugin remove 移除 profile 里的依赖与 bundle，配置随补丁删除，技能是 DSH 运行期提供的，项目目录本来就没有文件要清。

密钥不会自动从凭据库删除；storages/dsh-zrwang-plugin/ 会保留。要彻底清干净时手动删这个目录（state/ 和 patent/ 一起），并在设置里清空密钥。

四道护栏与降级方式

护栏都挂在 DSH 官方扩展点上，不靠提示词约束。拦不住时的默认行为是“少给能力”，不是“报错停摆”。

护栏挂在哪拦什么放什么
技能文件护栏 ctx.tools.guard 写 skills/ 或 ars/，包括通过符号链接指回插件目录的路径 只读工具与其他目录的写入
ARS 写作用域 tools/pre-execute Bucket A 子代理写阶段目录之外、用 shell、逃出 cwd、补丁越界 主会话、inline 角色、B/C/D 角色
MCP 工具隔离 ctx.tools.restrict + pre-execute 本会话没启用的 mcp__* 工具 本会话已启用的组件工具
接口同源 ctx.webServer 的 /dsh-zrwang-plugin/* 跨站请求、非 localhost Host、跨源 Origin 同源页面发来的读写请求
密钥不回显 设置页与凭据库之间 把密钥回填到界面、写 YAML、写日志 只显示「已设置 / 未设置」
技能内容不要手改。skills/ 和 ars/ 是 vendor 脚本按上游与改写规则生成的产物，手改会在下次同步时被覆盖。要调整内容，改 vendor/ 里的规则后重新运行生成脚本。

缺少运行环境

没选 Python、没装 lark-cli、MATLAB 没开时，对应技能或组件置灰，不影响其他技能。设置页会列出缺什么。

没有 MCP 管理器

headless / SDK 的 profile 里组件显示不可用，插件其他部分照常装配，不因为注册失败把宿主拖垮。

会话不完整

取不到工作目录时，侧栏请求返回明确错误；技能提供方拿不到 cwd 时退化为进程目录，不会列出无效候选。
