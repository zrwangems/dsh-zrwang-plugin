01

技能管理：按对话决定注入什么

DSH 默认从项目里的 .agents/skills/ 发现技能。技能一多就互相干扰，也难挑。插件把技能实体留在包内，用 DSH 官方的 ctx.skills 提供方按对话直接提供选中的那部分。

▤

三级目录树

工程 / 科研 / 办公三组，共 329 个技能：MATLAB、Simulink、Nature、Zotero、专利、OfficeCLI、PPT Master、飞书 Lark 等。搜索按名称、类别和中文说明过滤，展开状态会被记住。

工程 230 · 科研 52 · 办公 47（含飞书 28）
◎

每个对话一份选择快照

对话第一次打开侧栏时继承当前选择，之后勾技能、开分组、开 ARS 都只写这个对话。切回旧对话时，侧栏和技能提供方一起恢复它自己的状态，互不影响。

snapshot 存在 storages/dsh-zrwang-plugin/state/session-selection.json
◈

模式：项目级快捷模板

把一组常用选择存成模式，套用后写入当前对话。支持基于此新建、重命名、删除；工作区自动模式改名后升级为项目级，同项目所有工作区可见。

模式不会反过来改别的对话
⇢

不写项目目录

技能只从插件包读取，不建 <项目根>/.agents/skills，也不做目录联接。选中即出现，取消即摘除，项目目录保持干净。

官方提供方：ctx.skills.registerProvider

说明、详情与上游链接

每个技能有一行中文说明；详情按 Markdown 渲染表格、列表和代码，也能直接打开 SKILL.md；项目根的 ↗ 在浏览器打开对应 GitHub 仓库。

02

MCP 组件：宿主启动，按对话给工具

两个服务器由 DSH 的 ctx.mcpManager 在宿主级注册、多个对话取并集保持运行；每个对话再用官方 ctx.tools.restrict({ deny }) 把没勾选的工具从工具列表、提示词和执行里一起移除。

∑

MathWorks组件 自动

工程技能组打开且确有工程技能注入时，注册 matlab-mcp。插件自带 MATLAB MCP 可执行文件和完整的 Simulink Agentic Toolkit 运行时，共 14 个工具：MATLAB 基础 5 个 + Simulink 9 个。

MATLAB 侧需先执行一次 satk_initialize(...) 共享会话

03

ARS：一条独立的学术研究流水线

ARS 放在 ars/，不进 skills/，也不计入 329 个技能。默认关闭，勾选后注入 5 个流水线技能，并提供 16 个 /ars-* 命令。

5 个技能 目录 ars/skills/

academic-pipeline academic-paper academic-paper-reviewer deep-research sr-screener

多角色流程会在执行前自动打开 DSH 的「智能体团队协作」并投递授权说明；只有在无法改动该开关时（例如子会话）才提示手动开启。

16 个命令 按侧栏开关动态注册

/ars-plan/ars-full/ars-lit-review /ars-reviewer/ars-revision/ars-3w /ars-abstract/ars-citation-check/ars-disclosure …共 16 个

命令只在 ARS 打开时注册，关掉即注销；运行说明由脚本生成并入库，不在运行期改写包内文件。

设置：一个出口，没有第二份配置

所有能填的项都在「设置 → 插件 → My DSH」里。非密钥写 profile 补丁的 config，密钥只进 DSH 凭据库；保存后用新值立即重算，不需要重启 DSH。

配置流向 设置页是唯一入口

① 你填写的值

设置卡片 / 下拉选择

  • 非密钥字段
  • 密钥字段（只显示已设置 / 未设置）

② DSH 官方存储

不新建插件配置目录

  • cordis.patch.yml → 本插件条目的 config
  • .credentials.yaml → 每个密钥一个 ref

③ 运行期注入

技能子进程直接读

  • ctx.shellEnv 注册 DSH_ZRWANG_*
  • Python 启动钩子把 *_CRED 映射回上游标准变量名

上游技能自带的 .env、向导和配置读取代码已经删除或改指向这里；要改默认值就改插件设置，不要去改技能目录。

05

安装之后，往 .dsh 里写了什么

默认 $DSH_HOME 是 ~/.dsh，下面以 web profile 为例。插件本体之外，没有插件自己的配置目录；运行期数据都在 DSH 的持久化根 $DSH_HOME/storages/dsh-zrwang-plugin/ 下，插件升级保留。

~/.dsh/
├── .credentials.yaml        # 只放你填的密钥（0600）
├── profiles/
│   └── web/
│       ├── package.json       # 依赖 + dsh.profile.bundles
│       ├── cordis.patch.yml   # 本插件条目与 config
│       └── node_modules/
│           └── dsh-zrwang-plugin/   # 插件本体
│               ├── host/ client/ lib/
│               ├── catalog/ skills/ ars/
│               ├── mathworks/ vendor/licenses/
│               ├── docs/ locale/ cordis.patch.yml
│               └── （包内没有 cache/）
├── storages/
│   └── dsh-zrwang-plugin/       # 运行期，插件升级保留
│       ├── state/              # 选择态/门禁/模式/事件
│       └── patent/             # 设置页指定；建议放这里：vault/ patent-map/ oa/ outputs/
└── （没有 zrwang-plugin-config/）

写入时机

  • 安装时：pnpm 把包装进 profile 的 node_modules，并在 package.json 里记录依赖与 bundle。
  • 第一次改设置：非密钥写 cordis.patch.yml 的本插件条目；密钥写 .credentials.yaml。
  • 运行期：选择态、门禁、模式、界面展开、事件和专利数据只写 $DSH_HOME/storages/dsh-zrwang-plugin/（state/ 与 patent/）。
  • 卸载时：插件目录删除；storages 下这份数据不随卸载自动删（插件升级也保留），要彻底清就手动删 storages/dsh-zrwang-plugin/；凭据库里的密钥不会自动删除。

包体积主要来自 329 个技能的素材（PPT 模板、字体等）和随包分发的 MathWorks 运行时；安装前留足磁盘空间。

位置内容谁写入卸载后
$DSH_HOME/profiles/<profile>/node_modules/dsh-zrwang-plugin/ 插件本体：host / client / lib、329 个技能、5 个 ARS 技能、MathWorks MCP exe 与 Simulink 工具包、目录树、文档与许可。包内资产运行期只读。 DSH 插件安装（pnpm） 随目录删除
$DSH_HOME/profiles/<profile>/package.json 多一条插件依赖；dsh.profile.bundles 里多一条本插件，启动时装配它的补丁层。 DSH 插件安装 随卸载移除
$DSH_HOME/profiles/<profile>/cordis.patch.yml 本插件条目的 config：生图模型、检索凭据的非密钥部分、Python 路径、MCP 自动恢复开关等。包的 insert 行随包分发，不写进 profile。 插件通过 configEditor 写入 条目可能保留，建议手动删
$DSH_HOME/.credentials.yaml 只有你在设置里填过的密钥，每个一个 ref（如 ZRWANG_IMAGE_API_KEY）；文件权限 0600，设置页只回显“已设置”。 DSH 凭据服务 不自动删，需手动清
$DSH_HOME/storages/dsh-zrwang-plugin/state/ selection.json、gates.json、presets.json、session-selection.json、ui.json、events.jsonl、python-candidates.json、ars-deps.json。 插件运行期 升级保留，卸载后手动删
$DSH_HOME/storages/dsh-zrwang-plugin/patent/（设置页可改） 专利技能的向量索引与工作数据；设置页填了「专利数据目录」才会用，不填则专利技能置灰。 专利技能（vault/、patent-map/、oa/、outputs/） 升级保留，卸载后手动删
<项目根>/.agents/skills/ 不写。技能不再通过项目目录或目录联接注入，改用 DSH 官方技能提供方。 — 从未创建
$DSH_HOME/zrwang-plugin-config/ 不写。旧版本目录只在升级时迁移一次并删除，新安装不会再出现。 — 无

一句话：插件本体在 profile 的 node_modules 里，配置在 profile 补丁和凭据库，状态在 DSH storages 的 dsh-zrwang-plugin/ 里；不往项目目录写技能，也不再建第二个配置目录。另外，pnpm 会在 profile 目录维护 pnpm-lock.yaml 和 node_modules/.pnpm 的依赖副本，这是 DSH 包管理的产物，不是插件自己写的。

  • index.mjs：装配、生命周期、agent 事件
  • routes.mjs：/dsh-zrwang-plugin/* HTTP 接口

  • skill-provider：ctx.skills 按对话提供技能
  • session-selection / tool-restrictions：会话快照与工具过滤

08

边界与还没验证的部分

已经过 Linux 自检和假宿主冒烟；真实 DSH 页面、Windows 桌面和 MATLAB 会话还需要实机验证。

!

MCP 仅 Windows 可用。MATLAB MCP 是 Windows 可执行文件，Windows MCP 依赖 Windows 桌面；其他平台组件行显示“当前 profile 不支持”。

!

MATLAB 要先共享会话。需要 R2023a+，并在 MATLAB 里执行一次 satk_initialize(...)（内部会 shareMATLABSession()）。

!

工具过滤不回溯历史。restrict 影响之后的步骤和请求；已经发出的历史消息里残留的工具定义不会回头修改，新开一轮或新对话就干净了。

!

重建有短暂空窗。自动恢复会先卸旧实例再挂新实例，这一小段时间该组件的工具暂时不在工具表里，连上后会重新出现。

!

自愈会一直重试。只要组件还开着、MATLAB 一直没回来，插件会按最长 5 分钟的间隔继续尝试；不想让它重试就在设置里关掉自动恢复。

!

还没有 Windows 实机结论。本页与测试都在 Linux 完成，Windows 上的 MATLAB 掉线恢复、桌面 MCP 和真实页面还需要你那边跑一遍。
